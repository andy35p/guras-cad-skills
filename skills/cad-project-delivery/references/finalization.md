# 最终成果和清理

1. 读取任务、更改说明、修订链、交付包内容和文件时间。为每个独立子任务列出保留清单，记录选择依据。文件名“最终版”或最大时间戳都不是单独的定案证据。
2. 保留原生源文件、交换备份、最终预览/打印文件、实际依赖、必须的许可、必要假设说明。多个楼层、零件、房间分别保留末版。不可从版本链判断时，保留有价值的分支并说明，不凭猜测删除唯一内容。
3. 默认保留一份展开后的最终目录；如用户需要发送再保留一份从它重打包的最终 ZIP。中间 ZIP 即使包含不同文件名也先核对内容。
4. 用 SHA256 和文件清单确认保留文件有效且不依赖即将删除的外链、XREF、贴图、字体或本地素材目录。PSD/SKP要原生重开，CAD做对象审计，图片/PDF要目视检查。
5. 用户已经要求清理时可以执行。脚本 finalize_outputs.py 需要明确的 root、keep、files，files记录所有待审文件的相对路径与sha256。先不带 --apply 预览；应用时先整体校验所有散列，再删清单中未保留的文件。
6. 路径必须在明确项目 outputs 根目录内。拒绝 ..、绝对相对路径混用、符号链接和重解析点。只删除清单里的文件。新出现文件保留并报告。占用文件不强删，报告路径。
7. work 可能含用户原图或参考资料。只有来源已识别的日志、测试转换件和生成预览可清理，不能整个工作区递归删除。被技能引用的脚本、有效输入和必要素材要先保留。
8. 删除完成后验证最终文件数量、哈希及交付包内容，保存选择依据和删除结果。不要声称结构审计证明设计已经正确，也不要把整理后的旧文件称为重新设计或重新验收。
